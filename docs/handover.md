## Product pages (Task 9)

- **Live table widget not reproduced:** the Framer "Table" widget's own chrome (its `Search...` box, `Previous`/`Page X of Y`/`Next` pager, CSV export) isn't rendered — `SpecTable` just lists every row of `docs/scrape/tables.json`'s already-hydrated data instead, which is why `scripts/verify.mjs` carries a dedicated `WIDGET_CHROME` ignore list for every `/produkter/*` route. The sub-navigation pill labels (`Product.subnav`, e.g. rørender's "Rørender rette/90 grader/45 grader") are static text on the live site too, not links — `components/produkter/SubnavLabels.tsx` renders them as plain `<span>` pills, not `<Link>`s.
- **Table-to-heading pairing is by document order, not by heading text:** the brief's sketch matches each table to the live scrape's H3 by `precedingHeading`, but four routes (fett, fylleutstyr, banjokoblinger, slanger) have tables with no heading at all. `scripts/gen-produkter.mjs` instead pairs the k-th contiguous run of table-cell text in a product's `blocks` to the k-th entry in that route's `tables.json` list, purely by position, and throws if the counts don't match. Table text-runs are recognised by membership in that route's set of `tables.json` header/cell strings (trimmed) — a non-member text block mid-run (the widget's own "Page X of Y" pager, or an occasional cell whose whitespace doesn't exactly match, e.g. fett's `"-30  til 150"` double space) is discarded since the run's real data always comes from `tables.json`; a non-member text block *outside* a run is kept as `Product.intro` (only fylleutstyr has one — a caption between its first group's images and its first table: "Fyllepresse til sentralsmøreanlegg for fettpatron iht. DIN 1284").
- **Images per table are not capped at two:** the brief's prose describes "up to two" images per table, but two of the eleven routes' first group have more — skruhylser has 3 (a diagram + two product photos), fylleutstyr has 4 (two diagram+photo pairs). Capping would drop real, visible content: a live image-count probe (mirroring `scripts/verify.mjs`'s own counting logic) against `https://www.elba.no/produkter/skruhylser` and `/fylleutstyr` confirmed the live page really does render all of them, and the generated `lib/produkter.ts`'s per-table image counts now match the live unique-image count exactly on every route checked (skruhylser 9/9, fylleutstyr 7/7, fett 3/3, rørender 14/14). `ProductTables` renders a single image full-width (no card, matching fett's product photo), and two-or-more in a two-column grid wrapping as needed, each on a light card (`#ebeef5`, sampled from the reference screenshots) — the scrape doesn't distinguish "diagram" from "photo" blocks, so both get the same card treatment; live only puts the card behind photos, so a diagram (already a white-background PNG) sits inside a faint extra border. Not fixed — would need a per-image role the scrape doesn't provide.
- **Adjacent no-image tables aren't grouped side-by-side:** on live, a table with its own images (e.g. rørender's "Forsinket stål (Zn-Ni)") and the very next table with none (its "Syrefast (316 / V4A)" sibling) sit in a two-column row sharing the first table's images. `ProductTables` instead stacks every `ProductTable` entry vertically, each with its own optional images row — all the same content and reading order, just single-column instead of the live page's occasional two-column pairing. `scripts/verify.mjs` doesn't check layout, only text content and image counts, so this doesn't affect verify.
- **Nine routes have sub-navigation, not eight:** all eleven product routes except `fett` and `skruhylser` carry `href: null` label links in the scrape (banjokoblinger, forlengere, fyllenippler, fylleutstyr, lynfittings, rørender, skottgjennomføring, slanger, snittringmatur).

## Articles (Task 10)

- **`— Skralli` → `— Elba` in every `<title>`:** all five `docs/scrape/artikler__*.json` carry the live page's real `<title>`, which ends in `— Skralli` (Skralli is Elba's new Icelandic co-owner's own company, and elba.no's Framer site was seemingly cloned from skralli.is without updating this one string). `scripts/gen-artikler.mjs` rewrites it to `— Elba` (`Article.metaTitle = j.title.replace(/ — Skralli$/, " — Elba")`); `tests/artikler.test.ts` locks this in (every `metaTitle` ends with ` — Elba`, none contain `Skralli`). The body copy itself does say "Skralli" where it's actually about the acquisition (nytt-eierskap) — that's real content, left untouched.
- **No visible publish date:** none of the five live article pages show a date — Framer's own `<time>` element renders empty on all of them, and no scrape block anywhere matches a date pattern. `Article.date` is typed `date?: string` but the generator never sets it and no template renders a date line.
- **Two H1s, kept:** every article's DOM has a second `<h1>` right after the breadcrumb (`Article.subtitle`) — on nytt-design it's verbatim identical to the title H1; on the other four it's a distinct sentence. Rendered either way (as its own `<h1>`, matching live), not skipped when it repeats the title.
- **Body reading column is narrower than the standard `Container`:** measured against `docs/reference/artikler__nytt-eierskap.desktop.jpg` and `artikler__velge-system.desktop.jpg` at 1440px — both start their breadcrumb and body text at x≈241px, not the container's own x≈50px edge — i.e. a ~960px column centered inside the 1340px site container. `app/artikler/[slug]/page.tsx` wraps breadcrumb + body in `mx-auto max-w-[960px]` to match.
- **nytt-eierskap's scrape glues three pull-quotes' closing quote mark directly onto their attribution** with no space (e.g. `…selskapene."sier Villi…`) — confirmed against a fresh live capture (`scripts/verify.mjs`) that the real page has a space there. `scripts/gen-artikler.mjs`'s `splitGluedQuote()` fixes this; one of the three instead glues on a "- Ronny, daglig leder" byline, which live renders as its own line, so that one splits into two `text` blocks instead of just gaining a space. Without this fix, `verify` failed only on `/artikler/nytt-eierskap` (missing=4).
- **No inline bold spans, no bullet grouping:** live's own HTML has inline `<strong>` runs inside sentences (e.g. velge-system's intro paragraph) and real `<ul>` bullet lists (most visibly on velge-system and passiv-og-aktiv-overvaaking). `scripts/scrape-formatting.mjs` did capture these as `list`/`bold` annotations once (see `docs/scrape/formatting.json`), but a later `scrape.mjs` re-run (the footer-detection fix) regenerated `docs/scrape/artikler__*.json` fresh afterwards and the annotations were never merged back in — confirmed by comparing mtimes and grepping for `"list"`/`"bold"` keys (absent from every current artikler scrape file). `ArticleBlock`'s `bold`/`list` fields and `ArticleBody`'s `BulletList`-grouping code are implemented per the type but are dead code against today's data: every body paragraph renders as plain text, and velge-system's bullet groups render as individually-spaced `<p>`s instead of a tight list — visibly more spread out than the reference screenshot. Re-running `scrape-formatting` against the current scrape would restore this; out of scope for Task 10.
- **No italic pull-quote / lede styling:** live gives nytt-eierskap's opening paragraph and its three `"…"` pull-quotes a distinct italic-gray treatment (the pull-quotes also get a left border). `ArticleBlock`'s `text` type has no such distinction (only a whole-block `bold` flag) and the scrape doesn't mark which paragraph is the "lede" either (nytt-design's own first paragraph is plain, not italic, so it isn't a fixed "first paragraph after the subtitle" rule) — rendered as plain paragraphs, a known, accepted visual gap versus the reference screenshots.
